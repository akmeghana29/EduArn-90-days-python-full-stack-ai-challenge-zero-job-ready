==========================================================
                 FLASK AI INTEGRATION
==========================================================

----------------------------------------------------------
1. What is Flask AI Integration?

Flask AI Integration means connecting a Flask web
application with an AI model through an AI API.

For example:

User
  ↓
Flask Frontend
  ↓
Flask Backend
  ↓
OpenAI / Gemini API
  ↓
AI Response
  ↓
Flask Backend
  ↓
User

This allows us to add AI features to normal web
applications.

----------------------------------------------------------
2. Why Integrate AI with Flask?

Flask can act as the backend between the user and
the AI API.

We can build:

• AI Chatbots
• AI assistants
• Text summarizers
• Question-answering systems
• Resume analyzers
• AI content generators
• Code assistants
• Document analysis applications
• AI-powered customer support

11. Flask Route

The Flask route receives a request from the frontend.

Example:

@app.route("/ask", methods=["POST"])
def ask():

    question = request.json["question"]

    # Call AI API here

    return {"answer": "AI response"}

----------------------------------------------------------
12. User Request

Suppose the frontend sends:

{
    "question": "Explain Flask"
}

Flask receives the JSON data.

The backend extracts:

question = request.json["question"]

----------------------------------------------------------
13. Creating the Prompt

The backend can create a prompt using the user's input.

Example:

prompt = f"""
You are a helpful Python tutor.

Answer this question in simple language:

{question}
"""

The prompt is then sent to the AI API.

14. OpenAI Integration Concept

Basic flow:

Flask

↓

OpenAI Client

↓

Model

↓

Prompt

↓

Response

Example concept:

from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="MODEL_NAME",
    input="Explain Flask"
)

answer = response.output_text

The exact model name should be selected from the
currently available OpenAI models.

18. Handling Errors

AI API requests can fail.

Possible reasons:

• Invalid API key
• API quota exceeded
• Rate limit
• Network error
• Invalid request
• Model unavailable
• Server error

Use exception handling.

Example:

try:

    # AI API call

except Exception as e:

    return {
        "error": "Something went wrong"
    }, 500

----------------------------------------------------------
19. Input Validation

Never blindly accept user input.

Example:

if not question:
    return {
        "error": "Question is required"
    }, 400

This prevents empty requests from being sent to
the AI API.

It is better to keep AI API code separate from Flask
routes in larger applications.

Example:

→ Flask routes

ai_service.py

→ OpenAI/Gemini API logic

This keeps the application organized.

----------------------------------------------------------
30. Important Security Rule

The API key should stay on the backend.

Correct:

Frontend
   ↓
Flask
   ↓
AI API

Incorrect:

Frontend
   ↓
AI API using exposed API key

The frontend should never contain your private
AI API key.

Problem:

401 / Authentication Error

Cause:

Invalid or missing API key.

--------------------------------

Problem:

429 / Rate Limit Error

Cause:

Too many requests or insufficient quota.

--------------------------------

Problem:

500 / Server Error

Cause:

Server-side problem.

--------------------------------

Problem:

No response from Flask

Possible causes:

• Incorrect route
• Flask server stopped
• Incorrect URL
• Incorrect request format
• AI API error

40. Common Interview Questions

Q1. How do you integrate AI with Flask?

Create a Flask route that receives user input,
construct a prompt, call the AI API using an SDK,
process the response, and return the result to
the frontend.

--------------------------------

Q2. Where should the AI API key be stored?

In an environment variable or secure secret manager,
not directly in the source code or frontend.

--------------------------------

Q3. Why use POST for an AI endpoint?

Because the client needs to send data such as the
user's question to the backend.

--------------------------------

Q4. Why separate AI logic from Flask routes?

To keep the application modular, maintainable,
testable, and easier to modify.

--------------------------------

Q5. Can Flask directly call OpenAI or Gemini?

Yes.

Flask can use the provider's Python SDK or make
HTTP API requests from the backend.

--------------------------------

Q6. Can the frontend directly call the AI API?

Technically some APIs can be called from client-side
applications, but private API keys should not be
exposed there. For server-side secrets, the safer
architecture is:

Frontend → Flask Backend → AI API

--------------------------------

Q7. How can conversation history be maintained?

Store previous messages in application memory,
a database, or another appropriate storage system,
then provide the relevant conversation context to
the model.
