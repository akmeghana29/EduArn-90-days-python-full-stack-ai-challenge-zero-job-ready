==========================================================
                 EC2 DEPLOYMENT NOTES
==========================================================

----------------------------------------------------------
1. What is EC2?

EC2 stands for Elastic Compute Cloud.

Amazon EC2 is a cloud service provided by AWS that allows
us to create and run virtual servers on the cloud.

Instead of running an application only on our own computer,
we can deploy it on an EC2 server so that it can be accessed
over the internet.

----------------------------------------------------------
2. Why Use EC2?

EC2 can be used to:

• Host web applications
• Deploy Flask applications
• Run backend servers
• Host APIs
• Run Docker containers
• Process background tasks
• Scale applications

----------------------------------------------------------
3. Basic EC2 Deployment Architecture

----------------------------------------------------------
4. What is an EC2 Instance?

An EC2 Instance is a virtual server running in AWS.

It provides:

• CPU
• RAM
• Storage
• Operating System
• Network connectivity

We can choose the instance type depending on the
application's requirements.

----------------------------------------------------------
5. Basic Deployment Requirements

Before deployment, we need:

• AWS Account
• EC2 Instance
• Linux-based operating system
• SSH access
• Flask Application
• Docker (if deploying using Docker)
• Required security rules

----------------------------------------------------------
6. Creating an EC2 Instance

Basic process:

1. Open AWS Console.
2. Go to EC2.
3. Choose "Launch Instance".
4. Select an AMI.
5. Choose an instance type.
6. Create or select a key pair.
7. Configure network settings.
8. Configure storage.
9. Launch the instance.

----------------------------------------------------------
7. AMI

AMI stands for Amazon Machine Image.

It provides the operating system and other configuration
needed to launch an EC2 instance.

A common choice for Flask applications is a Linux-based
AMI.

----------------------------------------------------------
8. Instance Type

An Instance Type determines the resources available to
the EC2 server.

It determines:

• CPU
• Memory
• Network performance

For learning and small projects, a small instance type
is generally sufficient.

----------------------------------------------------------
9. Key Pair

A key pair is used to securely connect to an EC2 instance.

It consists of:

• Public Key
• Private Key

The private key is kept securely by the user.

Example file:

my-key.pem

----------------------------------------------------------
10. Connecting to EC2 Using SSH

Linux/macOS:

chmod 400 my-key.pem

Then:

ssh -i my-key.pem ec2-user@PUBLIC_IP

The exact username depends on the AMI being used.

For Ubuntu-based instances, the username is commonly:

ubuntu

----------------------------------------------------------
11. Security Groups

A Security Group acts as a virtual firewall for an
EC2 instance.

It controls incoming and outgoing network traffic.

Common inbound rules:

SSH
Port 22

HTTP
Port 80

HTTPS
Port 443

Application Port
Example: 5000

----------------------------------------------------------
12. Why Port 22?

Port 22 is used for SSH connections.

It allows us to remotely access the EC2 server.

----------------------------------------------------------
13. Why Port 80?

Port 80 is the standard port for HTTP traffic.

It allows users to access a web application using:

http://PUBLIC_IP

----------------------------------------------------------
14. Why Port 443?

Port 443 is the standard port for HTTPS traffic.

HTTPS provides encrypted communication between the
client and server.

----------------------------------------------------------
15. Installing Docker on EC2

After connecting to the EC2 instance, Docker can be
installed according to the Linux distribution being used.

After installation, verify:

docker --version

        ↓

        ↓

Push Image / Copy Project

        ↓

EC2 Instance

        ↓

----------------------------------------------------------
17. Copying Project to EC2

One approach is to clone the project repository directly
on the EC2 instance.

Example:

git clone <repository-url>

Then:

cd project-folder

----------------------------------------------------------
18. Building the Docker Image on EC2

Inside the project directory:

docker build -t flask-app .

This creates the Docker image on the EC2 server.

----------------------------------------------------------
19. Running the Flask Container

Example:

docker run -d -p 5000:5000 flask-app

This maps:

EC2 Port 5000
       ↓
Container Port 5000

----------------------------------------------------------
20. Accessing the Flask Application

If the EC2 public IP is:

PUBLIC_IP

The application can be accessed using:

http://PUBLIC_IP:5000

The EC2 Security Group must allow inbound traffic
on port 5000.

----------------------------------------------------------
21. Production Architecture

For a more production-ready setup, the application can
use:

User
  ↓
HTTPS
  ↓
Nginx
  ↓
Flask Application
  ↓
Database

Docker can be used to containerize the Flask application.

----------------------------------------------------------
22. Nginx

Nginx is a web server and reverse proxy.

It can:

• Receive HTTP/HTTPS requests
• Forward requests to Flask
• Serve static files
• Handle SSL/TLS
• Improve application architecture

Instead of exposing Flask directly, we can use:

User
  ↓
Nginx
  ↓
Flask

----------------------------------------------------------
23. Environment Variables

Sensitive information should not be hardcoded.

Examples:

DATABASE_URL
SECRET_KEY
API_KEY
AWS_ACCESS_KEY

Environment variables can be used to store configuration
values.

Example:

docker run -e SECRET_KEY="value" flask-app

----------------------------------------------------------
24. Database in EC2 Deployment

The Flask application can connect to:

• MySQL on the same server
• MySQL running in another server
• Amazon RDS
• Another managed database service

For production applications, a managed database such as
Amazon RDS is commonly preferred over running the database
directly inside the application container.

26. Updating the Application

When code changes:

1. Push changes to GitHub.

git add .

git commit -m "Updated application"

git push

2. Connect to EC2.

3. Pull the latest changes.

git pull

4. Rebuild the Docker image.

docker build -t flask-app .

5. Stop the old container.

docker stop container_id

6. Remove the old container.

docker rm container_id

7. Start the new container.

docker run -d -p 5000:5000 flask-app

28. Common Deployment Problems

Problem:

Application is not accessible.

Possible causes:

• Security Group does not allow the required port.
• Container is not running.
• Incorrect port mapping.
• Flask application is not listening correctly.
• EC2 instance is stopped.

----------------------------------------------------------
29. Important Flask Configuration

When running Flask inside Docker/EC2, the application
must listen on an externally accessible interface.

For example:

app.run(host="0.0.0.0", port=5000)

Using 0.0.0.0 allows the application to accept connections
from outside the container.

----------------------------------------------------------
30. EC2 vs Localhost

Localhost:

Application runs on your own computer.

Example:

http://127.0.0.1:5000

--------------------------------

EC2:

Application runs on an AWS server.

Example:

http://PUBLIC_IP:5000

31. Common Interview Questions

Q1. What is EC2?

EC2 is an AWS service that provides virtual servers
for running applications.

--------------------------------

Q2. What is an EC2 Instance?

A virtual server running in AWS.

--------------------------------

Q3. What is a Security Group?

A virtual firewall that controls network traffic
to and from an EC2 instance.

--------------------------------

Q4. What is SSH?

SSH is a secure protocol used to remotely connect
to a server.

--------------------------------

Q5. Why is port 22 used?

Port 22 is the standard port for SSH.

--------------------------------

Q6. Why is port 80 used?

Port 80 is the standard port for HTTP traffic.

--------------------------------

Q7. Why use Docker with EC2?

Docker packages the application and its dependencies
into a consistent environment that can easily be run
on the EC2 server.

--------------------------------

Q8. What is Nginx?

Nginx is a web server and reverse proxy commonly used
in front of backend applications.

--------------------------------

Q9. Why use 0.0.0.0 in Flask?

It allows Flask to listen for connections on all
network interfaces, making the application accessible
from outside the container or server.

----------------------------------------------------------
Summary

EC2 deployment involves running an application on an AWS
virtual server. A Flask application can be packaged using
Docker, transferred or cloned onto an EC2 instance, and
then run inside a Docker container. Security Groups control
network access, SSH provides remote server access, and
Nginx can be used as a reverse proxy for a more
production-ready architecture.
